  Each scenario is built from scratch in-memory (no JSON).
  Five strategies run on identical input; per-axis winners are
  tagged so the surviving strategy per attack is visible at a glance.

  ── all-critical --------------------------------------------
     Every patient CRITICAL — legacy_priority collapses to a single value (11)
     patients=20  workers=5  tasks=100  total_work=1500 min

     strategy                 ms    OT  max-OT  brch    cov     runtime   ticks

     FCFS × Hungarian        300      0      0     0  100/100  1273.0 µs    51 (+145d)  ← best ms / lowest OT
     Priority × Greedy       300      0      0     0  100/100   534.2 µs    20  ← best ms / lowest OT
     Priority × Hungarian    300      0      0     0  100/100  1610.8 µs    53 (+155d)  ← best ms / lowest OT
     Priority × Fair(α=0)   300      0      0     0  100/100   520.2 µs    20  ← best ms / lowest OT

     Priority ordering degenerates to deterministic tie-hash; ordering becomes effectively FIFO-ish.

  ── tight-shift ---------------------------------------------

     Perfect balance → 0 OT. Any imbalance → immediate OT. Exposes which matchers actually balance vs just ride slack.

  Reading the table:
    ms      = makespan, minutes
    OT      = total overtime across all workers, minutes
    max-OT  = worst single-worker overtime, minutes
    brch    = number of commits that pushed a worker past their shift
    cov     = scheduled / total tasks (incomplete = INCOMPLETE tag)
    ticks   = match() invocations; (+Nd) = Hungarian re-queue events
